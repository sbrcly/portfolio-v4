4. The margin rule

A, recommended. The margin gains a third line. Line two is currentEmployer: inside III, the last [data-employer] whose top is at or above the midline, resolved by the same observer rule as current-chapter.ts (rootMargin 0 0 -50% 0, recompute at scroll end, jumps held until the scroll ends); outside III it is null. Line three is the lit entry, exactly as today (litEntry() in Margin.tsx), now "01.2 Prompt Lab". Each line is its own fader with the light's timing: 400 out, 200 gap, 600 in; instant on load and under reduced motion. Line two never changes because of a plate, and line three never changes because of an employer, so a scroll inside one employer moves one line at most.

B. The margin is unchanged: one line, the lit entry, now unnumbered ("Prompt Lab"). The employer is named by the sticky row in the measure instead. Cost: a second pinned element on the page, and three entries in a row (01.3 to 01.5) during which the margin's line is empty.

Lit-plate rule. Unchanged: nearest centre, inside the 25svh band, 10% hysteresis, scroll-end settle. Only the candidate set changes: plates in III now number six (Prava, Prompt Lab, the extension diagram, the console, the arbitrage table, the schedule). Spec blocks and text-only entries are not candidates.

Employer header behaviour. A: left behind. The margin carries the employer, so the header need not. B: pinned, under the frame (top 96 / 80 on phone), for the length of its block; the next employer's row pushes it out. The row is not data-fade, since at the top edge it would otherwise sit at .15.

5. Data model

type Employer = {
  id: string;             // "faith-platforms"; index "01" is derived from position
  name: string;           // "Faith Platforms Inc."
  shortName?: string;     // what the margin reads: "Faith Platforms". Falls back to name.
  role: string;           // "Sole engineer"
  years: { from: number; to: number | "now" };
  note?: string;          // "ticket brokerage"; shown dim after the role line
  projects: Project[];    // any count, in display order
};

type Project = {
  id: string;             // "prava"; index "01.1" is derived
  name: string;           // the margin's lit entry uses this
  meta: string;           // "2025 to now · iOS · App Store"
  sentence: string;
  stack: string[];        // joined with " · "
  plate?: Plate;          // absent: A renders spec, B renders text-only
  spec?: { key: string; value: string }[];   // A's ruled block; 3 to 5 rows
  caseStudy?: { href: string; label?: string };  // "Read the case study"
  writeUp?: { repo: string };                     // "Write-up: Odds-Display-Public"
  verify?: { href: string; label: string }[];     // "App Store", public repos
  status?: "live" | "internal" | "proprietary";
};

type Plate =
  | { kind: "image"; src: string; alt: string }
  | { kind: "screens"; images: { src: string; alt: string }[] }   // Prava's 4-up (2 on phone)
  | { kind: "video"; src: string; poster: string; seconds: number }
  | { kind: "diagram"; component: "ExtensionDiagram" };

Indices are positions, never stored: adding a project to Etainement renumbers nothing above it and only the entries after it within 02. The margin's second line (A) is `${index} ${shortName ?? name}`; its third line is `${index}.${n} ${project.name}`.
